# Infrastructure

Everything Health24 runs on in AWS Mumbai, per environment (sp7-plan.md, T16).

**Nothing here has been applied.** It is formatted, validated and reviewed, and
CI checks it on every push — with `-backend=false`, so no account is involved.
The first real apply will find something; that is a task in SP8 rather than a
surprise (Decision V1). What this buys in the meantime: the whole shape of the
deployment is reviewable, reproducible and costs nothing until somebody decides
to spend.

## Layout

| File | What is in it |
| --- | --- |
| `versions.tf` | Pinned Terraform and provider versions, the S3 backend, default tags |
| `variables.tf` | Everything an environment can differ in, with validation |
| `network.tf` | VPC, subnets, NAT, routes, the S3 endpoint, security groups |
| `data-stores.tf` | RDS, ElastiCache, the documents bucket and their KMS keys |
| `secrets.tf` | Secret **names** in Secrets Manager. Never values |
| `iam.tf` | The execution role, and one task role per service |
| `ecr.tf` | Image repositories, immutable tags, scan on push |
| `ecs.tf` | The cluster, five services, and the migration task |
| `alb.tf` | The load balancer, target groups, listeners and host rules |
| `alarms.tf` | The four alarms that mean something, and the topic they publish to |
| `outputs.tf` | What a deploy and an operator need afterwards |
| `environments/*.tfvars` | Staging and production, differing only in size and protection |

## Checking it

```bash
terraform fmt -check -recursive -diff
terraform init -backend=false
terraform validate
```

Those three are what CI runs, and they need no credentials. A `plan` needs an
account; see `docs/deployment.md` for what to do once there is one.

If Terraform is not installed, Docker will do:

```bash
docker run --rm -v "$PWD:/work" -w /work hashicorp/terraform:1.9 fmt -check -recursive -diff
docker run --rm -v "$PWD:/work" -w /work hashicorp/terraform:1.9 init -backend=false
docker run --rm -v "$PWD:/work" -w /work hashicorp/terraform:1.9 validate
```

## Two rules that shaped most of it

**Nothing that holds patient data has a route from the internet.** The load
balancer is the only public thing; tasks are in private subnets; the database
and the cache have no internet route at all, and S3 is reached through a VPC
endpoint. Data residency is a validation rule on the region variable rather than
a comment, because `planning.md` §11 makes it a legal requirement.

**No secret passes through Terraform.** Secrets are created empty and filled in
once by a person, the database's master password is generated by AWS into
Secrets Manager, and there is no `secret_version` resource anywhere — a value
written by Terraform is a value in state, and state is a file in a bucket that
more people can read than can read Secrets Manager (DF3).
